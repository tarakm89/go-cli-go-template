A plan is for work large enough that the order of steps matters. Small specs go
straight to code — do not write a plan out of habit.

| Plan | Status | Covers |
| --- | --- | --- |
| [0001](0001-template-foundation.html) | Done | Bringing the template to v0.1.0 |

A plan should say what ships in what order, what each step depends on, and how
each step is verified. If a step has no verification, it is not a step.

Plans are working documents. When the work is done, mark it and leave it — the
next person planning something similar wants to see how the last one actually
went, not a tidied version.
